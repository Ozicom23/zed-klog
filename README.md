# zed-klog

klog support in Zed.

[klog](https://klog.jotaen.net) is a plain-text file format for time tracking.
This extension adds support for `.klg` files:

- Syntax highlighting
- Outline of records by date, and bracket matching for `(8h!)`
- Auto-indent: Enter on a date line starts an entry, and a date typed on an
  indented line moves back to the start of the line
- Tags such as `#home-office` are selected as one word
- A language server, [`klog-ls`](klog-ls), built on klog's own parser:
  - Errors for invalid klog, with klog's own messages, and warnings for
    unclosed open ranges, entries in the future, overlapping ranges and
    records over 24 hours
  - Each record's total next to its date (enable inlay hints, see below)
  - Hovers with the totals of a record, the duration of a range, and the time
    tracked with a tag
  - Completion of tag names and tag values that are used in the file
  - Code actions to start and stop an open range at the current time, and to
    add a record for today, the way `klog start`, `klog stop` and
    `klog create` do

## Installing as a dev extension

1. Make sure `rev` in [`extension.toml`](extension.toml) points to a commit that
   contains the grammar (see below).
2. In Zed, run `zed: install dev extension` and select this folder.

The extension looks for the language server in this order:

1. The path in the `lsp.klog-ls.binary.path` setting.
2. `klog-ls` on the PATH.
3. The latest [GitHub release](https://github.com/Ozicom23/zed-klog/releases).
   This only works once the repository is public and a release exists.

Zed shows inlay hints only when they are enabled. To show the totals, add this
to your Zed settings:

```json
"languages": {
  "klog": {
    "inlay_hints": { "enabled": true }
  }
}
```

## Repository layout

- `extension.toml`: the extension manifest.
- `src/lib.rs`: the Rust part of the extension, which starts the language server.
- `languages/klog/`: language config and the queries for highlighting, outline
  and brackets.
- `tree-sitter-klog/`: the tree-sitter grammar, written from the
  [klog specification](https://github.com/jotaen/klog/blob/main/Specification.md).
  - `grammar.js`: the grammar rules.
  - `src/scanner.c`: a small external scanner for line breaks and indentation.
    klog's indentation style is set per record by its first entry, which decides
    whether an indented line is a new entry or continues an entry summary.
  - `src/parser.c` and the rest of `src/`: generated by `tree-sitter generate`.
    These files are committed, because Zed compiles the parser from them.
  - `test/corpus/`: parser tests.
- `klog-ls/`: the language server, written in Go. It uses klog's own parser,
  so it validates files exactly like the klog CLI.

## Changing the grammar

```bash
cd tree-sitter-klog
npm install
npx tree-sitter generate
npx tree-sitter test
```

Then commit, including the regenerated `src/` files, and set `rev` in
`extension.toml` to the new commit so that Zed picks up the change. Zed only
rebuilds the grammar when you reinstall or rebuild the dev extension.

Changes to the queries in `languages/klog/` apply after a rebuild, with no new
commit needed.

## Changing the language server

It needs [Go](https://go.dev) 1.26 or later.

```bash
cd klog-ls
go test ./...
go build -o klog-ls .
```

To try a local build in Zed, point the `lsp.klog-ls.binary.path` setting to
it, and run `editor: restart language server`.

## Releasing the language server

Pushing a tag like `v0.2.0` runs
[`.github/workflows/release.yml`](.github/workflows/release.yml), which tests
`klog-ls`, builds it for macOS, Linux and Windows, and publishes a GitHub
release. The extension downloads the binary from the latest release.
